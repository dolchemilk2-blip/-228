# Доступ к Монтажке только для купивших

Монтажка открывается только тем, у кого есть доступ. Ссылкой поделиться бесполезно: по ней
человек увидит страницу входа, а после входа своим аккаунтом — «доступа нет, введите код».

## Как это устроено

- **`montage/index.html` — страница входа.** Самой Монтажки в ней нет.
- **Монтажка лежит в базе Firebase.** База отдаёт её только аккаунтам с доступом. Это проверяют
  правила на сервере Firebase — из браузера их не обойти.
- **Вход — через Google.** Паролей нет, забыть нечего.
- **Доступ открывается кодом активации.** Один код — один аккаунт. Второй раз тот же код не сработает.
  Можно выдать доступ и вручную, без кода.
- **Одно устройство за раз.** Вошли тем же аккаунтом на втором устройстве — на первом Монтажка
  встаёт на паузу с кнопкой «Продолжить здесь». Работа при этом не пропадает. Отдать свой аккаунт
  другу можно, но пользоваться вдвоём неудобно: вы будете выбивать друг друга.
- **Отключить доступ можно в любой момент.** Даже открытая вкладка закроется в течение минуты.
- **Управление — в `montage/admin.html`.** Там загрузка новой версии, коды и список покупателей.
  Пускает только вашу почту.
- **Всё работает на бесплатном тарифе Firebase (Spark).** Карта не нужна.

## Шаг 0. Закрыть исходники — обязательно

Сейчас репозиторий `-228` **публичный**. В нём лежат исходники Монтажки и все её прошлые сборки.
Пока это так, любой может скачать старую сборку прямо с GitHub, и вход ничего не защищает.

GitHub → репозиторий → **Settings** → **General** → в самом низу **Danger Zone** →
**Change repository visibility** → **Make private**.

⚠️ На бесплатном тарифе GitHub Pages у приватного репозитория не работает. Выключится и личный
сайт из этого репозитория. Где тогда разместить страницу входа — в разделе
[«Где разместить сайт»](#где-разместить-сайт) внизу.

## Шаг 1. Создать проект Firebase

Для Монтажки заведите **отдельный** проект — не тот, где живёт чат.

1. <https://console.firebase.google.com> → **Add project** → название, например `montazhka`
   → **Continue**.
2. Google Analytics можно выключить → **Create project**.

## Шаг 2. Включить базу

1. Слева: **Databases & Storage → Realtime Database** → **Create Database**.
   На телефоне меню прячется под **☰**.
   ⚠️ Нужна именно **Realtime Database**, а не Firestore.
2. Регион — **Belgium (europe-west1)**.
3. **Start in locked mode** → **Enable**. Правила вставим на шаге 5.

## Шаг 3. Включить вход через Google

1. Слева: **Security → Authentication** → **Get started** → вкладка **Sign-in method**.
2. **Google** → переключатель **Enable** → выберите свою почту в «Project support email» → **Save**.
3. Там же, вкладка **Settings** → **Authorized domains** → **Add domain**. Впишите адрес сайта
   без `https://` и без пути, например `dolchemilk2-blip.github.io`. `localhost` там уже есть.

## Шаг 4. Вписать ключи в сайт

1. Слева **⚙️ → Project settings** → **General** → прокрутите вниз до **Your apps** → значок
   **`</>`** (Web) → любое название → **Register app**. Галочку про Hosting ставить не нужно.
2. Скопируйте значения из показанного `firebaseConfig` в файл **`montage/access/config.js`**:

```js
  firebase: {
    apiKey:      "AIzaSy...",
    authDomain:  "montazhka.firebaseapp.com",
    databaseURL: "https://montazhka-default-rtdb.europe-west1.firebasedatabase.app",
    projectId:   "montazhka",
    appId:       "1:123456789:web:abc123"
  },
  buyUrl: "https://…",   // куда ведёт кнопка «Купить Монтажку» (магазин, Telegram, форма)
  contact: "@вашник"      // куда писать при проблемах: email или @telegram
```

`databaseURL` копируйте как есть — в разных регионах он выглядит по-разному.

Эти ключи не секретные: они просто говорят странице, к какому проекту обращаться. Защищают
правила из следующего шага.

## Шаг 5. Опубликовать правила базы

1. Откройте **`…/montage/admin.html`** на сайте → **Войти через Google** своим аккаунтом.
2. Админка скажет «Этот аккаунт — не владелец» и покажет **правила базы** — в них уже вписана
   ваша почта. Нажмите **Скопировать правила**.
3. Firebase → **Realtime Database** → вкладка **Rules** → удалите всё → вставьте → **Publish**.
4. Вернитесь в админку → **Проверить ещё раз**. Откроется управление.

Правила кладут в базу вашу почту как владельца. Сменили почту — повторите шаг 5 с новой.

## Шаг 6. Загрузить Монтажку

В админке, раздел **Сборка Монтажки** → выберите файл **`montage.html`** → **Загрузить сборку**.

Файл `montage.html` — это собранная Монтажка: `node build.mjs` кладёт её в `montage/dist/`.
В репозиторий она не попадает. После каждого обновления Монтажки загрузите новый
`montage.html` так же. Покупатели получат новую версию при следующем открытии.

## Шаг 7. Коды и продажа

**Коды.** В админке, раздел **Коды активации** → сколько штук и пометка (например, где продаёте)
→ **Создать коды** → **Скопировать новые**.

**Как продавать.** Подойдёт любой способ, где после оплаты покупатель получает текст:
- магазин цифровых товаров, который сам выдаёт код;
- Telegram-бот;
- вручную: пришла оплата переводом — отправили код.

**Без кода.** Покупатель входит на сайт, вы находите его в разделе **Покупатели** →
**Выдать доступ**.

**Что видит покупатель.** Открывает сайт → **Войти через Google** → вводит код → Монтажка
открывается. Дальше заходит без кода: браузер помнит вход, а Монтажка хранится у него и заново
скачивается только после обновления.

**Возвраты и нарушения.** В разделе **Покупатели** → **Отключить**. Вернуть — **Вернуть доступ**.

## Что защищено, а что нет

| | |
|---|---|
| Поделиться ссылкой | ✅ бесполезно: без доступа Монтажка не придёт |
| Один код на двоих | ✅ нельзя: код закрепляется за первым аккаунтом |
| Отдать свой аккаунт | ⚠️ можно, но работать сможет только один человек за раз |
| Отключить покупателя | ✅ сразу, открытая вкладка закроется в течение минуты |
| Вытащить код Монтажки из своего браузера | ❌ технически можно — как у любого сайта, который работает в браузере. В каждую выданную копию вшита почта покупателя (`<meta name="montage-license">`), так что по всплывшей копии видно, чья она |

## Лимиты бесплатного тарифа

База Firebase на тарифе Spark бесплатно даёт 1 ГБ хранения и 10 ГБ скачивания в месяц.
Монтажка весит около 0,8 МБ, а при передаче сжимается. Скачивается она один раз на устройство
и потом только после обновлений. Этого хватит на тысячи покупателей. Если когда-нибудь не
хватит — Firebase предложит перейти на Blaze (оплата по факту).

## Где разместить сайт

Страница входа — это обычные файлы: `montage/index.html`, `montage/admin.html` и папка
`montage/access/`. Их можно положить на любой хостинг. Сама Монтажка приходит из базы.

После шага 0 GitHub Pages на бесплатном тарифе не работает. Варианты:

1. **GitHub Pro** (около 4 $ в месяц). Pages снова работает, адрес не меняется, личный сайт
   тоже живёт. Но Pages публикует все файлы репозитория, включая исходники Монтажки. Поэтому
   публикацию нужно переключить на GitHub Actions, чтобы выкладывались только нужные файлы.
2. **Бесплатно — Firebase Hosting** в том же проекте. У Монтажки будет свой адрес
   `montazhka.web.app`, выкладка — автоматически при каждом обновлении через GitHub Actions.
   Нужно один раз сделать ключ доступа и положить его в секреты репозитория. Личному сайту
   понадобится своё место: его можно так же выложить на Firebase Hosting своего проекта.

## Если что-то пошло не так

| Что видно | В чём дело |
|---|---|
| «Сайт ещё не подключён к Firebase» | Не заполнен `access/config.js` (шаг 4) |
| «База закрыта: правила доступа ещё не опубликованы» | Не сделан шаг 5 |
| «Этот адрес сайта не разрешён для входа» | Адрес сайта не добавлен в Authorized domains (шаг 3) |
| «Вход через Google не включён» | Не включён провайдер Google (шаг 3) |
| «Браузер не открыл окно входа» | Разрешите всплывающие окна для сайта |
| Жёлтая плашка «ссылка открыта внутри приложения» | Instagram, TikTok и подобные не пускают во вход Google — откройте ссылку в обычном браузере |
| Админка: «Этот аккаунт — не владелец» | Правила опубликованы с другой почтой — повторите шаг 5 этим аккаунтом |
| «Доступ есть, но Монтажка ещё не загружена» | Не сделан шаг 6 |
| «Код не подошёл» | Опечатка, код уже активирован другим аккаунтом или отключён в админке |

## Для разработки: проверка на эмуляторах

Всё можно проверить у себя, без настоящего Firebase:

1. Нужны Java и `firebase-tools`.
2. В папке с `firebase.json` (эмуляторы `auth` и `database`) положите правила, заменив в них
   `ADMIN_EMAIL` на тестовую почту.
3. Запустите `firebase emulators:start --project demo-montage --only auth,database`.
4. Раздайте `montage/` любым локальным сервером и откройте `http://localhost:…/index.html?emu`
   (или `admin.html?emu`).

С `?emu` страница ходит в эмуляторы, а не в настоящий Firebase — и только на `localhost`.
Кнопку входа в режиме эмулятора заменяют `window.__montageAccess.signIn('почта')` и
`window.__montageAdmin.signIn('почта')`.
